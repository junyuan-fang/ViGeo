# 01 原理：把相机轨迹看成 SE(3) 上的一条曲线

> 读者假设：熟悉 ViGeo/VGGT 类模型，不一定熟悉微分几何。每节末尾的"代码"指向本分支中的实现。

## 1. 为什么"位姿"不该当成 R⁷ 里的向量

ViGeo 的 camera head 对每帧输出 `[t(3), q(4)]`，原版 `camera_loss` 直接做 `L1(t) + L1(q)`。
但旋转全体 SO(3) 是一个 **3 维弯曲流形**，单位四元数是它的双重覆盖 S³（`q` 和 `-q` 是同一个旋转）。在 R⁴ 里量距离有两个问题：

1. **不是真实误差**：同样是 θ 度的旋转误差，绕不同轴时 L1 值不同（见 [图 1](02_figures.md#图-1四元数-l1-vs-测地距离)）。
2. **符号不连续**：代码用 `standardize_quaternion` 强制 `w ≥ 0`。当 GT 本身转了 θ_gt 度，预测只要往"另一侧"偏 180°−θ_gt 度，`q` 就会被翻成 `-q`，L1 突然跳到 ~2。
   相对首帧的旋转很大（转身、环绕拍摄）的 clip 正好落在这个区域。

**测地距离**：SO(3) 上两点之间最短路径的长度，就是相对旋转的转角
```
d(R₁, R₂) = ‖Log(R₁ᵀ R₂)‖ ∈ [0, π]
```
这里 `Log: SO(3) → so(3) ≅ R³` 是对数映射，输出轴角向量 ω（方向 = 转轴，长度 = 转角）。

> 代码：`so3_log`、`so3_geodesic_angle`、`geodesic_camera_loss`（`src/loss/riemannian.py`）。
> `so3_log` 用 `2·atan2(‖v‖, w)` 而不是 `acos`，因为 `acos` 在 θ→0 时导数趋于无穷。

**这一步本身不是 novelty**（Hou et al. 2018 已经做过），它是后面曲线损失的地基。

## 2. 视频 = 一条曲线：速度与加速度

一个 clip 的预测位姿 `T_0, …, T_{S-1}` 是 SE(3) 上的**离散曲线** γ。曲线的几何量按阶数分为：

| 阶 | 连续形式 | 离散形式（本分支） | 物理含义 |
|---|---|---|---|
| 0 | γ(s) | `T_i` | 每一帧在哪 |
| 1 | γ⁻¹γ̇（body velocity） | `ξ_i = Log(T_i⁻¹ T_{i+1})` | 相机这一步怎么动（在自身坐标系下） |
| 2 | ∇_γ̇ γ̇（协变加速度） | `a_i = ξ_{i+1} − ξ_i` | 运动方式怎么变化：抖动、急转 |

具体在 SE(3) 上（`T = [R | t]`，相机到世界），本分支取 body frame 下的 SO(3)×R³ 积度量：
```
ξ_i = ( ω_i, v_i ) = ( Log(R_iᵀ R_{i+1}),  R_iᵀ (t_{i+1} − t_i) )
```

### 为什么 `a_i = ξ_{i+1} − ξ_i` 可以叫"协变加速度"

在 Lie 群上用左平移把各点的切向量都搬回单位元（左平凡化）之后，曲线的速度变成 Lie 代数里的一条曲线 ξ(s)。
对左不变度量，左平凡化后的协变加速度是（Euler–Poincaré / Euler–Arnold 形式）
```
∇_γ̇ γ̇  ↔  ξ̇ − ad†_ξ ξ        （ad† 是 ad 关于该度量的伴随）
```
SO(3) 上的标准度量是**双不变**的，此时 `ad†_ξ = −ad_ξ`，附加项等于 `ad_ξ ξ = [ξ, ξ] = 0`。于是协变加速度就是 `ξ̇`，离散化后就是 `ξ_{i+1} − ξ_i`。
平移部分在 body frame 下取平坦度量，近似成立。完整 SE(3) 度量下的修正项留作后续工作（README §6）。

### 每一阶能"看见"什么误差

用一个平面玩具（SE(2)，与代码同构）验证（[图 2](02_figures.md#图-2每一阶看见不同的误差)）：

| 误差类型 | 0 阶 | 1 阶 | 2 阶 |
|---|---|---|---|
| 整条轨迹整体平移/旋转了一下（gauge） | 大 | **0** | **0** |
| 每帧独立抖动 | 小 | 中 | **大** |
| 速度有系统偏差（漂移） | 大（随时间累积） | **中，恒定** | 很小 |

结论：**0 阶看位置，1 阶看局部运动（≈ RPE），2 阶专门看抖动/不连贯**。论文强调的 "consistent" 更多体现在 1、2 阶。
另外 1、2 阶对整条轨迹的全局刚体变换**严格不变**，因为 `(G T_i)⁻¹(G T_{i+1}) = T_i⁻¹ T_{i+1}`，所以不依赖 `normalize_gt` 把哪一帧当成参考。

> 代码：`relative_twist`（ξ）、`relative_motion_loss`（1 阶）、`curve_accel_loss`（2 阶）。
> 1 阶旋转项比较的是 `Log((ΔR_pred)ᵀ ΔR_gt)`，而不是 `ω_pred − ω_gt`，这样可以避开 π 处的割迹。

## 3. 为什么是"匹配 GT 曲线"，而不是"让曲线变平滑"

最直接的想法是加一个平滑先验 `Σ‖a_i‖²`（视频生成里 VGGRPO 就这么做）。但 ViGeo 的训练数据采样（`BaseDataset.sample_sequence`）有三个特点：

1. 帧间步长在 `1..max_interval` 之间随机，时间参数化不均匀；
2. 走到序列末尾会**反向**，GT 轨迹本身带尖点；
3. 有 30% 的概率**打乱帧序**。

在这三种情况下，**GT 轨迹自己的"加速度"就很大**：打乱帧序时，平滑先验在 GT 上的值约是正常情况的 900 倍（[图 3](02_figures.md#图-3训练采样下平滑先验会惩罚-gt-本身)）。用平滑先验就会和点图/位姿监督打架。

匹配式损失 `‖a_i^pred − a_i^gt‖` 没有这个问题：pred 和 GT 用的是**同一套离散参数化**（同样的帧顺序和步长），所以：
- 完美预测的损失恒为 0，与采样方式无关；
- 同等程度的抖动，在三种采样方式下的损失几乎一样（0.150 / 0.152 / 0.164）。

所以这里**不需要时间戳，也不需要改数据管线**。

## 4. 更深一层：曲线空间上的度量（novelty 所在）

把三阶损失加权求和，相当于在"SE(3) 上所有离散曲线组成的空间"里定义了一个**二阶 Sobolev 型距离**：
```
D(γ_pred, γ_gt) = λ₀ Σ d(T_i)  +  λ₁ Σ ‖ξ_i^pred ⊖ ξ_i^gt‖  +  λ₂ Σ ‖a_i^pred − a_i^gt‖
```
这把 VO 里常见的"位姿误差 + 相对位姿误差"推广成了一个**有几何意义的曲线度量**。往下有两步自然的推进：

1. **弹性度量 / SRVF**（Celledoni 等，Lie 群上的形状分析）：先把曲线映到 `q(s) = ξ(s)/√‖ξ(s)‖`，再在 L² 下比较，这样得到的距离**对重参数化不变**，可以正面处理随机步长，代价是要知道帧号。
2. **结构化输出**：camera head 直接预测 `ξ_i`，再用 `T_{i+1} = T_i · Exp(ξ_i)` 积分出位姿，这样轨迹连续性由结构本身保证。

## 5. 数值细节清单

| 问题 | 处理 |
|---|---|
| θ→0 时 `acos` 的导数趋于无穷 | `2·atan2(‖v‖, w)`，并取 `‖v‖ = sqrt(‖v‖² + 1e-12)` |
| θ→π 时 Log 不唯一 | 相邻帧的相对旋转远小于 π，1、2 阶不受影响；0 阶与原版有相同局限 |
| 混合精度 | 轨迹损失强制 fp32（`video_depth_loss.py` 里有 autocast） |
| 预测平移尺度 | 与原版 `camera_loss` 一样先乘 `scale_i` 对齐 |
| clip 长度 < 2 或 < 3 | 1 阶、2 阶分别返回可求导的 0 |

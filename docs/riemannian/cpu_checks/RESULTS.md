> 所有检查都**只用 Python 标准库**（没有 torch / numpy / GPU / checkpoint），在 Python 3.9 上运行。
> 能验证的是**数学和设计是否成立**，不是 torch 代码本身（那要等装了 torch 跑 [`../smoke_test.py`](../smoke_test.py)）。

## 总结

| 方向 | 检查内容 | 结果 | 对优先级的影响 |
|---|---|---|---|
| **R0/R1** | loss 数学：Log/Exp、gauge 不变性、各阶分工、梯度有界、连续性 | ✅ 12/12 通过 | 维持 P0 |
| **R2** | 无训练平滑的上限 | ✅ 平滑轨迹上 RPE −82~93%；**急转弯时平滑反而有害** | 维持 P1；同时成为"为什么用匹配而不用先验"的证据 |
| **R3** | 法向 × 位姿公式（合成房间） | ✅ 真值上为 0；对位姿误差有线性响应；动态物体是真实风险 | 维持 P1；**实现时必须加 90% 截尾** |
| **R4** | 是否与现有点图 loss 冗余 | ⚠️ **作为 loss，尺度部分是冗余的**；作为评估指标非常准 | **降级**：尺度 loss 从 P1 降为 ✗；"闪烁指标"升为 P1 |

## R0 / R1：loss 的数学（`check_r1_losses.py`）

把 `src/loss/riemannian.py` 和 `mat_to_quat`、`quat_to_mat` **逐行移植**成纯 Python（[`geom.py`](geom.py)），再检查：

| 检查 | 结果 |
|---|---|
| `mat_to_quat` ↔ `quat_to_mat` 往返误差 | 8.9e-16 |
| `so3_log` 还原 Exp（角度从 1e-7 到 0.98π，500 个随机样本） | 最大误差 1.5e-12 |
| 预测 = 真值时三个 loss（arc / orbit / 急转弯三种轨迹） | 全部严格为 0 |
| 整体刚体变换：0 阶 > 0，1、2 阶 = 0 | 0 阶 = 3.82，1 阶 = 3e-16，2 阶 = 6e-16 |
| 每帧抖动：0 阶 < 1 阶 < 2 阶 | **200/200** 个随机种子都成立，2 阶 / 0 阶平均为 2.46 |
| 速度漂移：1 阶 ≫ 2 阶 | 1 阶 = 0.019，2 阶 = 0.0007 |
| 有限差分方向导数有界（预测 = 真值，以及有抖动时） | 最大 0.94，没有爆炸 |
| 新 loss 连续：转角每变 0.25°，loss 最多跳多少 | 0.0044（= 步长本身） |
| **原 loss 跳变**：同样 0.25° 的变化，四元数 L1 最多跳多少 | **1.934**（总转角跨过 180° 时） |

**结论**：数学上全部成立。最后一行给第 5 章图 1 补了一个干净的数字：原 loss 在**一个 0.25° 的变化**上跳了 1.93，新 loss 没有这个问题。

## R2：无训练平滑的上限（`check_r2_smoothing.py`）

**做法**：在 SE(3) 上用黎曼梯度下降求解
$\min_T \sum_i d(T_i, T_i^{\text{pred}})^2 + \lambda \sum_i \lVert \xi_{i+1} - \xi_i \rVert^2$，
平滑器写成了 `smooth_se3`，以后可以直接用在真实预测上。合成轨迹 24 帧，每种情况 3 个随机种子。

**取 RPE 旋转误差最小的 λ，与不平滑相比**：

| 轨迹 | 误差类型 | 最优 λ | RPE 旋转 | RPE 平移 | 加速度 loss | ATE |
|---|---|---|---|---|---|---|
| arc（平滑） | 抖动 | 64 | **−92%** | −76% | −96% | −20% |
| arc | 抖动 + 漂移 | 64 | **−82%** | −74% | −97% | −4% |
| orbit（环绕，大转角） | 抖动 | 64 | **−93%** | −91% | −98% | −49% |
| orbit | 抖动 + 漂移 | 64 | **−82%** | −70% | −98% | −2% |
| **急转弯** | 抖动 | **1** | −17% | **+11%** | −27% | **+69%** |
| **急转弯** | 抖动 + 漂移 | **1** | −17% | **+9%** | −27% | **+12%** |

**结论**：
1. **轨迹本身平滑时，二阶约束的收益上限非常大**（RPE −80~90%），而 ATE 几乎不变。这和第 6 章"故事讲一致性，不讲 ATE"的预期一致。
2. **漂移修不了**（ATE 只降 2–4%）。漂移是 1 阶误差，要靠 `relative_motion_loss`，不能靠 2 阶。
3. **急转弯时平滑有害**：λ ≥ 4 后 RPE 比不平滑还差（详表里 λ=64 时 RPE 旋转从 1.40° 涨到 2.85°）。这从反面证明了 R1 的设计：**和真值的加速度匹配，而不是要求加速度小**。匹配式 loss 在急转弯处的目标就是真值本身的急转，不会把它抹平。
4. ⚠️ 合成真值是完美光滑的，所以这是**乐观的上限**。真实数据要回答的是"模型的预测误差里，高频（抖动）成分占多少"。这需要拿到真实预测后用同一个 `smooth_se3` 再跑一次。

## R3：法向 × 位姿跨帧耦合（`check_r3_normal_pose.py`）

**做法**：用光线投射渲染一个合成房间（地板、墙、天花板，加一个转了 25° 的箱子），从两个相机拍，分辨率 64×48，得到深度和相机坐标系下的法向。然后计算 $\angle(R_j^\top R_i n_i(u),\ n_j(u'))$。

| 检查 | 结果 |
|---|---|
| **先行验证**：真值法向 + 真值位姿 | 中位数 **8e-16°**，均值 0.51°（来自物体边缘少数像素） |
| 双线性采样（训练中 `grid_sample` 的做法） | 均值 1.12°：法向在深度边缘被混合 |
| **90% 截尾均值**（和 `normal_map_loss(ratio=0.9)` 同样的技巧） | 最近邻 5e-16°，双线性 0.000°：**边缘残差完全消除** |
| **R3b 信号**：相对旋转加 δ 度误差后的 loss | δ = 0.5/1/2/5° → 0.37/0.80/1.57/3.88°，斜率约 0.78，**线性响应** |
| 截尾后位姿信号是否保留 | 斜率 0.73–0.78，**保留** |
| 深度一致性过滤对遮挡的作用 | 不过滤 1.19°，过滤后 0.51° |
| **动态物体**（箱子在两帧之间转了 20°） | 过滤后仍有 **4.47°**：深度过滤挡不住 |
| 动态物体 + 90% 截尾 | 0.000°，但前提是动态像素占重叠区域不到 10% |

**结论**：
1. 公式在真值上严格为 0，第 7 章的先行验证通过。
2. 用预测相对旋转时（R3b），loss 对位姿误差有线性响应，可以给相机头提供梯度。
3. **实现时必须用截尾均值**，否则边缘和动态物体会污染 loss。截尾不损失位姿信号。
4. ⚠️ 动态物体占画面比例大时（人、车占多数的数据集），截尾也不够，**仍需排除动态数据集或使用动态 mask**。
5. ⚠️ 合成场景是分段平面，没有真实深度噪声。真实数据上真值的残差会更大，阈值要在真实数据上标定。

## R4：逐帧对齐曲线是否冗余（`check_r4_redundancy.py`）

**做法**：在合成房间的 8 帧点图上，给预测加"逐帧尺度闪烁"（$\log s_i \sim \mathcal{N}(0, \sigma)$）和"像素深度噪声"（ν）。然后移植 ViGeo 的尺度对齐（截断 L1 候选搜索，权重 1/z）和 `scale_invariant_pointmap_loss`，回答三个问题：

| 闪烁 σ | 噪声 ν | Q1：加入闪烁后现有 loss 变化 | Q2：现有 loss 的梯度是否把每帧推回共同尺度（方向一致率） | Q3：R4 估计的闪烁 / 真实闪烁 |
|---|---|---|---|---|
| 0.02 | 0.02 | +35% | 1.00 | 0.0167 / 0.0169 |
| 0.05 | 0.05 | +35% | 1.00 | 0.0418 / 0.0423 |
| 0.02 | 0.10 | **+2%** | 0.97 | 0.0170 / 0.0169 |
| 0.10 | 0.10 | +35% | 1.00 | 0.0840 / 0.0847 |
| （全部 12 种组合） | | | **最低 0.94** | **误差全部 < 2%** |

**结论**：
1. **Q2：作为 loss，R4 的尺度部分是冗余的**。现有 loss 虽然整个 clip 只用一个尺度，但它对每一帧的梯度方向在 ≥94% 的情况下都正确，已经在纠正闪烁。第 7 章担心的冗余在合成数据上**得到证实**。
2. **Q1：但闪烁在现有 loss 的数值里很难看出来**。噪声 10%、闪烁 2% 时，loss 只变了 2%。也就是说，**现有 loss 能纠正闪烁，但不能用来衡量闪烁**。
3. **Q3：R4 的估计器非常准**，在 10% 像素噪声下误差也小于 2%。**它应该被用作评估指标**（"视频深度尺度闪烁"），正好补上论文"一致性"故事里缺的那个指标。
4. ⚠️ 只验证了**尺度**部分。对齐曲线的旋转和平移部分（局部结构朝向的时间一致性）没有验证。chunk / online 推理时跨 chunk 的尺度漂移，也要在真实推理里检查。

## 验证之后的优先级调整

| ID | 原优先级 | 新优先级 | 理由 |
|---|---|---|---|
| R1 | P0 | P0 | 数学验证全部通过 |
| R2 | P1 | P1 | 上限显著；平滑器 `smooth_se3` 已经可用，等真实预测 |
| R3 | P1 | **P1，首选扩展** | 先行验证通过、信号清晰，风险也有了明确的应对（截尾 + 排除动态数据） |
| R4 尺度 loss | P1 | **✗** | 合成数据上和现有 loss 冗余 |
| R4 闪烁指标 | — | **P1（新）** | 估计准确，成本极低，直接支撑论文的"一致性"故事 |
| R4 旋转 / 平移部分 | P1 | P2 | 没验证，等真实数据上的闪烁指标结果再定 |
